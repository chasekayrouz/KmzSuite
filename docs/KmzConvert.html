KmzConvert

Guarded SCIEX X500 conversion · version 0.12.1 · updated 2026-10-18

Supported input

Choose a .wiff or .wiff2 entry point with matching .wiff and .wiff.scan sidecars beside it. WIFF2 is discovery/provenance only; its opaque database is not decoded. The reader is restricted to qualified X500-series SCIEX OS 2.x acquisitions, one sample/period, positive-mode TOFMS profile data with dependent MS/MS (IDA). Unsupported layouts are rejected rather than guessed.

App workflow

  1. Click Add Files to select one or more WIFF/WIFF2 files, or drop files into the input queue. Finder Open With also adds files. Repeated selections of the same path are ignored. Select queue rows (Cmd-click for multiple rows), then Remove to remove them before conversion.
  2. Choose one output mode: Full Profile (default) or Sparse Profile v3. Choose Folder sets one output directory for the entire queue. Each file keeps its input stem: sample.wiff or sample.wiff2 becomes sample.mzML in Full Profile or sample.sp.mzML in Sparse Profile. With a single file, Choose Output also lets you keep the existing custom-filename workflow.
  3. Click Convert or Convert Batch. Files run sequentially in queue order. The queue shows each result; progress shows overall files finished and current-file spectra after metadata loading. Settings and queue edits are disabled during conversion.

For a batch, existing destinations (including directories and symlinks) are skipped without opening the input. Two inputs with the same output name are handled in queue order: once the first creates that destination, the later file is skipped. No automatic renaming or overwriting occurs. File-specific conversion or launch failures appear in the log and queue; later files continue. A single-file conversion retains the backend's existing no-clobber error behavior.

Cancel stops the queue and interrupts the active converter, then waits for cleanup. Unstarted files are marked Not run. Quitting or closing the app during work also requests safe cancellation. The completion summary counts converted, skipped, failed, cancelled and unstarted files as applicable. Reveal Outputs selects successful outputs, even when another file failed. Save Log retains full messages and file headings.

Inspect metadata without converting is available with one queued file. It uses the existing inspect workflow and displays JSON plus diagnostics in the log, without writing a conversion file. Adding a second file turns inspection off.

The suite uses light panels, dark text, restrained borders and a green accent. Native buttons and input/radio/inspect controls retain visible enabled, disabled and focus states.

Mass correction (beta)

This optional control is off by default. Enable it and enter one or more expected_mz;RT_minutes pairs, one per line. Supply exact expected masses and approximate retention times in minutes. Mass must be finite and positive; RT finite and nonnegative. Malformed entries, duplicate pairs and enabled empty input are rejected.

Beta mass correction: applies one global offset to measured MS1 masses. Accuracy across the run is not guaranteed. MS2 masses remain uncorrected.

References are sought in original full MS1 profiles within RT ±0.45 minutes and mass ±1000 ppm, using chromatographic support, local spectral-lobe checks, repeated-scan precision and ambiguity checks. The observed mass is the median of local intensity-weighted centroids from at least three contiguous scans at or above 50% of the chromatographic apex intensity. A missing or ambiguous reference fails that file before output is written; edit the affected pair and retry. No reference is silently excluded.

Each acquisition receives a freshly fitted median reference ppm error, with equal weight per reference. Measured MS1 masses are divided by 1 + offset_ppm × 10⁻⁶, after native calibration/framing and before optional sparse filtering. Intensities, scan counts in Full Profile, RT, TIC, MS2 arrays and nominal precursor/isolation/window metadata remain unchanged. The same correction applies in both representations. Sampling checks remain active.

Automatic corrected names are sample.mc.mzML and sample.mc.sp.mzML; explicit destinations retain the usual naming rules. Versioned provenance records the beta correction, estimator, fitted offset, settings and reference observations. KmzViewer recognizes supported corrected sparse files even after renaming.

The log reports each expected/observed mass and RT, raw ppm error, fitted offset and calibration residual. If any fitting-reference residual exceeds 20 ppm, a prominent target-not-met warning is reported and the beta output is retained. A single-reference residual is zero by construction, with predictive accuracy unverified and cross-reference consistency unavailable. Small residuals at fitting standards do not guarantee accuracy across the run. Metadata inspection remains unchanged and ignores correction settings.

Multiple samples / runs

Before conversion, KmzConvert reads the sample identifiers stored in each WIFF. If any queued file contains multiple samples, a dialog lists those files with a checkbox for each sample ID (for example Sample 1 and Sample 2) and its output filename. All samples start checked. Uncheck unwanted runs, use Select All / Deselect All, then Convert Selected. At least one run must be selected unless single-sample files are also queued. Cancel closes the dialog without converting any files. Inspection uses the same selection dialog.

Each selected sample is exported independently, retaining its own scan times, calibration, precursors, TIC and matching optional DAD data. Names add _ID before the complete extension: sample_2.mzML, sample_2.sp.mzML, or sample.mc_2.sp.mzML. A custom destination is a base name and receives the same suffix. Single-sample files keep existing names and need no dialog. Existing per-sample outputs are skipped; an individual run failure does not prevent later selected runs. Mass correction fits each selected run independently.

The qualified multi-sample layout has one MS method or byte-identical MS method streams across methods. Files with differing MS methods are rejected rather than guessing which method belongs to a sample. This does not extend support to other instruments, negative polarity or multiple periods.

CLI

~/Applications/KmzSuite/kmzconvert --help
~/Applications/KmzSuite/kmzconvert --version
~/Applications/KmzSuite/kmzconvert sample.wiff --inspect
~/Applications/KmzSuite/kmzconvert sample.wiff2 -o converted.mzML
~/Applications/KmzSuite/kmzconvert sample.wiff --profile sparse -o converted.sp.mzML
~/Applications/KmzSuite/kmzconvert sample.wiff --mass-reference "200;3" --mass-reference "250;4"

Each invocation handles one run. Use kmzconvert sample.wiff --list-samples to list stored sample IDs as JSON, then kmzconvert sample.wiff --sample 2 --profile sparse -o sample.sp.mzML to produce sample_2.sp.mzML. Multi-sample files require an explicit --sample ID; the CLI never silently selects or merges runs. An explicit --sample also adds the ID suffix for a single-sample input. The suffix is added to the supplied base name, so do not add it twice. Repeating --mass-reference "expected_mz;RT_minutes" explicitly enables beta correction; the example pairs illustrate syntax and must be replaced with your known standards. --output is equivalent to -o. Full Profile is the default (--profile full). Without an output option, the CLI writes ./sample.mzML, or ./sample.sp.mzML with --profile sparse, in the current working directory. Sparse destinations are normalized to .sp.mzML, including explicit paths; sample.mzML becomes sample.sp.mzML. Only the selected representation is generated. The GUI uses the explicit destination it displays. Both frontends run the same core. No virtual environment or Terminal is needed for ordinary GUI use.

Optional DAD data

When matching sample.dad.scan and sample.dad.sidx files are present beside the WIFF acquisition, KmzConvert includes their qualified DAD spectra in the same mzML. Wavelength metadata and duplicate spectra, times and totals in the WIFF are cross-checked before inclusion. Signed absorbance and native scan times are preserved, with mAU converted to standard AU in mzML. Full Profile, Sparse Profile and mass-corrected outputs retain the same optical spectra; MS1 filtering/correction does not affect them.

If neither DAD sidecar is supplied, a brief note reports MS-only conversion. Missing, unreadable or unsupported DAD files produce a more visible warning naming the affected pair and still allow MS-only conversion. No confirmation is required and no partial optical data is exported. The embedded WIFF copies are not a fallback when sidecars are deliberately omitted. In KmzViewer, explicitly extract TWC/EWC traces to view DAD; opening the MS-only result shows no DAD warning. Auxiliary .timeseries.data remains unsupported.

The current DAD layout is qualified through internal agreement across six acquisitions, without an independent vendor-exported DAD reference.

Output safety and diagnostics

Existing files and symlinks are never overwritten. Conversion writes a temporary file beside the destination, then publishes a complete indexed mzML. Publication uses a no-clobber link when supported; otherwise an exclusive copy is size/checksum verified. Handled failures remove unfinished output. If final publication fails after writing completed, a recovery temporary file may be retained and its location is reported. Cancellation during publication may leave a complete output or recovery file; inspect the log. Allow space for two output copies on volumes using the fallback.

Exit codes are 0 for success, 1 for guarded format/I/O failures, 2 for argument errors, and 130 for an interrupted conversion. Errors and calibration/nominal-window diagnostics remain in the log. Some acquisitions record their first scans with a stale per-scan calibration copy: one scan after an empty startup period, or several consecutive scans (for example the first ~24 s) when recording starts immediately. The WIFF slot-table calibration is used only when that table is constant through startup, the stale copies share one value and the next scan matches the table exactly; the number of affected startup spectra is reported. Any other disagreement is rejected. Source-calibrated measured points are retained even outside nominal windows.

Output representations

Full Profile is the authoritative, full-fidelity default. Sparse Profile v3 is a substantially smaller, lossy MS1 representation for rapid inspection in KmzViewer. For each MS1 spectrum, the most frequent intensity estimates one detector event, so the cutoff follows changes in instrument sensitivity. Peaks whose apex exceeds 20 events and that span at least three points are kept down to 2 events, with one original boundary neighbor on each side. Each such peak is also followed into neighboring MS1 spectra at the same m/z while its apex stays above 8 events, so chromatographic peak edges are kept. Isolated noise and peaks that never exceed 20 events are omitted. Retained values are exact, without centroiding or smoothing. MS2, chromatograms and supported metadata are preserved. Embedded versioned provenance identifies the format even after renaming. Threshold and rendering settings are fixed.

Sparse Profile is not a replacement for archival/full-profile data where low-level profile information matters. Peaks that never exceed 20 events are absent and chromatographic tails at or below 8 events are cut; EIC sums omit their contribution, and short low-level connecting lines can remain. Use Full Profile for full-fidelity analysis. Incompatible source sampling is rejected for Sparse Profile.

Scientific limits

With correction disabled, Full Profile preserves calibrated measured masses/intensities, profile framing zeros, scan IDs/times, recovered precursor/energy metadata and the vendor TIC. Arrays are compressed 64-bit values, with indexed offsets and file checksum. No peak picking, smoothing or invented missing metadata is performed.

Precursor charge, isolation widths, activation type and absolute acquisition timestamp are not decoded. R/B instrument subtype is unresolved. Qualified DAD spectra are included from optional neighboring .dad.scan and .dad.sidx sidecars. Auxiliary time-series channels are not exported. Negative polarity, dynamic MS2 collision energy, multiple periods, differing MS methods across samples, WIFF2-only inputs and unqualified layouts are unsupported. Generic dissociation metadata is not a confirmed activation mechanism.

Open the output independently in KmzViewer or Kmz2Viewer. Conversion needs neither viewer nor the launcher. Runtime conversion is offline; raw acquisitions and reference data stay local.

Input compatibility

Version 0.3.0 uses the current KmzSuite conversion metadata. Both viewers reject obsolete suite outputs with: Legacy input received. Please reconvert using the current KmzConvert. Reconvert the original acquisition; renaming the mzML file or editing its header is not a migration. Ordinary third-party mzML remains supported.
