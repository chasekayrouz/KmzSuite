KmzCoMet

Comparative MS1 ion features · version 0.12.1 · updated 2026-11-05

Run an analysis

Open KmzCoMet from Spotlight or the KmzSuite launcher. Use Add WIFF Files (Command-O), Finder Open With, or file drops. Keep each acquisition’s matching .wiff and .wiff.scan together. WIFF2 entry points use those same sidecars. Qualified multi-sample containers prompt for their stored sample IDs. Each selected run becomes a sample column; aliases of the same run are ignored.

Drag input entries to reorder them; the first supplies the reference retention-time axis. Open Settings to adjust the next run, then choose Run Analysis (Command-R). Processing stays local and reads native full-profile MS1 arrays directly. It creates no large intermediate mzML files and never modifies acquisitions. Existing X500 reader qualification and sample/method guards remain active.

The initial app preset is the reviewed benchmark recipe: ±30 ppm mass tolerance, ±0.10-minute RT matching, ±0.15-minute measurement window, ±0.35-minute discovery context, discovery height 1000, evidence height floor 100, SNR 5, contrast 2, at least three support scans, maximum scan gap 0.05 minute, maximum RT shift 0.50 minute and five anchors. These are starting settings for review, not universal instrument defaults.

Use the Heights table

The main view contains a leftmost plotting checkbox, feature ID, m/z, aligned RT in minutes, polarity and each sample’s native peak height. Headers show acquisition names and stable sample IDs; hover for the full run label. The checkbox and identifying columns remain visible while sample columns scroll. Click headers to sort numerically, search by feature ID/mass/RT, or use inclusive mass and RT bounds. Blank bounds impose no restriction. Clear Filters restores all rows. Copy selected cells with Command-C. A measured zero remains zero; an unacquired value is blank. Heights are not probabilities.

No EICs are selected initially, including after reopening an analysis. Click a height to toggle that feature/sample EIC without clearing other picks; Space toggles a focused height. A row checkbox selects every sample in that feature, including zero/blank cells. A partial check means some samples are selected; click it to select the whole row. Click a checked box to clear the row. Picks survive sorting and filtering, and the selection count reports any hidden by filters. Clear EIC Selection clears all picks.

Analysis Details keeps Evidence, Measurements and Run in secondary tabs. Those tabs retain categorical evidence, per-sample metrics/flags, native sample IDs, input hashes, settings and alignment diagnostics. Weak or ambiguous evidence does not establish absence. Isotope/adduct rows remain separate ions rather than identified metabolites.

Plot selected EICs

Choose Plot EICs or press Command-E to open a new closable tab beside Heights. All selected feature/sample EICs appear together, stacked by default. Existing plot tabs keep their own traces and view while you make another selection. Switch back to Heights to change picks. The tab’s close button or Command-W closes the active plot; opening another analysis clears plot tabs and picks.

Each EIC sums native intensities within the feature’s common m/z ± the saved analysis’s ppm tolerance, including both endpoints, for its exact polarity. This matches KmzViewer’s EIC definition. The full acquisition is initially shown at original retention times, without RT alignment, smoothing or normalization. CoMet table heights instead use the strongest point in the mass window and only the feature’s measurement window, so plotted heights can differ and other peaks at the same mass remain visible. Plotting never changes the analysis.

Stacked / Overlay, Pan / Zoom box, Autoscale Y and Match Y use KmzViewer’s chromatogram controls. Retention-time zoom stays linked across stacked panes. Autoscale Y starts on and follows the visible time window; Match Y starts off. Turn Autoscale Y off for manual Y zoom/pan. Full view, F, Command-F or Command-0 restores the full time and Y bounds without changing these choices. Hover reports native RT and summed intensity. Larger stacks scroll vertically.

The scrollable Legend identifies source, sample, feature, m/z and polarity, with complete extraction metadata in tooltips. Check entries to show/hide traces, drag to reorder, and double-click to change a trace’s color. In Overlay, click a plot stroke or right-click a legend entry and choose Toggle emphasis for a darker, wider line. The Legend button hides/shows the legend. These choices belong only to that tab. There are no spectrum panes, Walk mode or double-click scan-inspection functions.

Extraction runs locally in the background and can be cancelled from Analysis → Cancel. All uncached selected masses in a sample share one read pass; a bounded session cache reuses extracted traces. Native WIFF EICs use an accelerated decoder and skip the zero bins added only to draw profile spectra. All measured signal, including weak points, is retained, and input integrity checks remain active. No sparse conversion or separate preparation pass is needed. Original acquisitions and required sidecars must be available and match the saved analysis. An unavailable or changed source leaves a labeled legend entry with the reason in its tooltip; other sources can still plot. Declared unacquired mass coverage leaves gaps, not measured zeros. No-scan and unspecified-coverage cases are explicit in legend labels/tooltips. Saved analyses retain results only; no raw spectra or full-run EICs are embedded. Closing tabs frees their retained trace references.

Explore feature PCA

Plot PCA opens a new closable tab containing all eligible features across all samples. It ignores table filters and EIC selections. Each point is a feature, and its pattern of heights across samples determines its position. No sample labels, controls or group assignments are needed. PCA uses saved heights, so it works without the original acquisitions.

Each row is divided by its own summed height; the sample columns are then mean-centered before PCA. Features with proportional profiles coincide even when their overall intensities differ. There is no sample normalization, background subtraction, log transform of profiles or evidence threshold. Color shows the original summed height, on a labeled logarithmic scale by default. Switch Color to linear if preferred. Depth does not change colors. Hover or click to see the feature ID, m/z, aligned RT, polarity, raw total and native units.

Drag to rotate, scroll or right-drag to zoom, and middle-drag to pan. Full view (F, Command-F or Command-0) resets the camera and fits all points. Axis selectors choose later components when available; selecting an already-used component swaps axes. Labels show explained variance, and the summary reports the total captured in view. Axes use equal scales. If the dataset has only one or two independent components, it forms a line or plane, with unused axes labeled “no variation.” Identical normalized profiles coincide without artificial jitter.

Command-click a point to open its EICs across every sample, exactly as for a full-row selection followed by Plot EICs. Table selections stay unchanged. Overlapping points open a searchable feature chooser. EICs still require the original acquisitions and use the usual source checks and session cache. Each PCA tab has independent view settings; opening another analysis clears the tabs. PCA never changes saved heights, evidence or exports.

Why some rows are omitted

A blank means no same-polarity MS1 scans covered that feature’s mass and retention-time window in that sample. For example, a run may end before the peak, acquire a different polarity, or exclude the feature’s mass range. A zero is an acquired measurement with no signal. Replacing a blank with zero would falsely imply a measurement was made.

For now, PCA omits a feature if any sample height is blank, and displays the omitted count. Measured zeros remain valid. All-zero rows are also omitted because their relative profile cannot be normalized. Numeric heights with partial-coverage, weak or ambiguous evidence remain included. Inspect Analysis Details → Measurements for coverage flags. Different acquisition coverage can therefore omit many rows.

Three PCs cannot reveal every unique pattern across hundreds of samples. Points that appear close may differ in components not shown; use explained variance, later components and EIC inspection. Separation is exploratory, not a significance test or proof of biological association. Row normalization gives weak and intense profiles equal influence, so weak noisy features can affect the geometry; summed-height colors retain the intensity context. Sample intensity biases are not automatically corrected.

Automatic history and Past Analyses

A completed analysis is automatically saved as a versioned .kmzcomet result under ~/Library/Application Support/KmzSuite/KmzCoMet/Analyses/. Filenames contain the analysis time, sample count and unique ID. Past Analyses opens a file browser at that location. A saved file can also be opened from Finder or dropped into the app.

Reopening restores the original complete results, timestamp, method/software version, settings and provenance. It does not rerun the method, check original paths or require the acquisitions to remain connected. Snapshots contain result data, not raw spectra or executable Python objects. The results are read-only. Settings changes apply to a subsequent run; reopening initially restores that analysis’s settings.

If automatic saving fails, the result stays in memory and is clearly marked unsaved. Use Retry Saving Analysis after resolving the storage issue. An unsaved result is not listed in Past Analyses. Closing an unsaved result requires an explicit choice. History files persist until you remove them; keep backups if needed. No history is uploaded.

Export

Export Heights as CSV writes the complete Heights matrix, including all rows regardless of current table filters. UTF-8 sample headers include filenames and stable/native sample identifiers. Export Excel writes the complete four-sheet analysis: Heights, Evidence, Measurements and Run. Both preserve blanks versus zero and retain weak measured values. Reopened analyses export their original timestamp and method/version. Choose a new filename: existing files and symlinks are never overwritten, including on ExFAT drives.

Cancellation and limitations

Cancel stops analysis, plotting or export cooperatively and removes incomplete staging. PCA cancellation waits for the current native matrix solve to finish before discarding its result. Closing or quitting waits for background readers to finish safely. A result already committed to history remains available even if cancellation arrives afterward. The interface remains responsive during calculations, loading, saving and export.

Direct WIFF support is limited to the converter’s qualified X500 positive-profile layouts; unsupported instruments/methods are rejected. The scientific baseline uses constant RT shifts and window heights, with the same unresolved crowding, broad-peak and low-signal limitations as the existing engine. Quantitative measurements remain unnormalized and provide no blank correction, metabolite identification or calibrated presence probability. PCA normalization is for visualization only. CSV and Excel are exports; the saved analysis is the app’s reopening format. Snapshots use schema 1 with bounded archive loading (128 MiB archive, 512 MiB expanded JSON). The current Excel worksheet-size limits also bound analyses.

Development

Launch with .venv/bin/python -m kmzcomet_app. The existing kmzcomet command remains available for scriptable mzML/WIFF-to-Excel work and keeps its original CLI defaults; the app uses the reviewed preset above. Tests redirect history/preferences through the suite’s local state root.
